# 5. Costs, capacity and resource needs

I would start with the existing team, tools, and test processes instead of hiring many people or buying new tools immediately. My goal would be to improve quality step by step while keeping costs under control.

1. Roles and skills needed
- Test Lead / QA: Plans testing, identifies risks, and improves the quality process.
- Developers: Test their own code, write automated tests, and fix defects.
- Business Analyst / Product Owner: Clarify requirements and acceptance criteria.
- Operations: Monitor production and help investigate incidents.

2. Central coordination vs development teams
- Centrally: Define quality standards, testing guidelines, risk assessment, and common metrics.
- Within development teams: Write and run tests, automate important workflows, fix defects, and take responsibility for quality.
This keeps standards consistent while allowing teams to work independently.

3. Where to invest first
- Automate repetitive regression and critical tests.
- Improve existing test environments and test data.
- Use existing tools wherever possible before purchasing new ones.
- Add monitoring to detect data problems and integration failures early.

4. Expected costs
- Short term: Time spent reviewing existing tests, improving automation, preparing test data, and setting up monitoring.
- Medium term: Some ongoing maintenance of automated tests and environments, plus possible tool or infrastructure costs if a clear need is identified.

5. Expected benefits and measurement
I would measure improvement by tracking:
- Fewer defects found in production.
- Faster test execution and feedback.
- Less manual regression testing.
- Fewer repeated incidents.
- More reliable and accurate data.
- Less time spent fixing problems after release.

Two possible options
- Minimum option: Use the existing team and tools, focus on high-risk areas, and automate the most important tests.
- Recommended option: In addition, allocate regular team capacity for automation, test data and environment improvements, and quality monitoring.

My recommendation: Start with the minimum option, measure the results, and gradually move towards the recommended option where the benefits justify the investment. This improves quality without requiring a large upfront budget.
